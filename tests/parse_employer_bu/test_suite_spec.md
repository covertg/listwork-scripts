# Test Suite Specification: `parse_employer_bu.py`

## Purpose

Create a pytest-based test suite for the `parse_employer_bu.py` script, which parses Dartmouth employer-provided bargaining unit lists into cleaned CSVs for use with Broadstripes. This is a one-shot-per-term script used by GOLD-UE Local 261 organizers; the tests exist to make the script maintainable across generations of rank-and-file leadership.

## Repo context (verify before starting)

Assumed layout:
```
<repo-root>/

├── program_mapping.toml        # production mapping file
├── tests/
│   └── (may contain tests for other scripts)
```

If the actual layout differs, ask the user before proceeding. All paths below are relative to `<repo-root>`.

## Fixture files to generate

### `fixtures/generate_sample.py`
A standalone script that produces `sample_list.xlsx`. Running it should be idempotent and regenerate the fixture. Include a `if __name__ == "__main__":` block. The script uses pandas to write a small DataFrame (8-12 rows) with these columns matching the real employer format:

- `Employee ID` (or whatever the real ID column is — use `EMPLID` as a placeholder, document in comment)
- A fullname column (name it `NAME` — the real column name varies; document this)
- A program column (name it `PROGRAM` — same note)
- `ADDRESS_LINE1`, `ADDRESS_LINE2`, `TOWN/CITY`, `ST`, `ZIP`

Include rows exercising:
- standard name + standard program + full address
- name with middle initial
- name with no middle
- name with multiple first names
- hyphenated last name
- apostrophe in last name (e.g., `"O'Brien, Sean"`)
- address with missing `ADDRESS_LINE2` (use `""` or NaN — match what employer sends; document assumption)
- program with " PROGRAM" suffix that should be stripped
- program without " PROGRAM" suffix
- a zip code starting with `0` (regression guard for string vs. float loading)

All names must be obviously fake (`"Smith, John"`, `"García López, María"`, etc.). All addresses must be obviously fake.

### `fixtures/sample_program_mapping.toml`
Covers every program used in `sample_list.xlsx`. Format matches production:
```toml
"Computer Science" = ["Employer Name", "PhD"]
"Biology" = ["Employer Name", "PhD"]
# etc.
```

### `fixtures/real/.gitkeep`
Empty file. Include a `README.md` alongside it explaining:
- this directory is gitignored
- users can drop real employer `.xlsx` files here (with dates in the filename per the script's requirement)
- users must also provide a matching `program_mapping.toml` (or symlink the production one)
- tests in `test_real_data.py` will automatically run on any files found

## `conftest.py` contents

Define these fixtures:

- `sample_xlsx_path` — returns `Path` to `fixtures/sample_list.xlsx`
- `sample_mapping_path` — returns `Path` to `fixtures/sample_program_mapping.toml`
- `sample_dataframe` — returns a small in-memory `pd.DataFrame` shaped like a BU list, for unit tests that don't need file I/O. Use the same row shape as the xlsx fixture but constructed inline.
- `tmp_mapping_file` — factory fixture that writes a custom mapping dict to a temp `.toml` file and returns the path; useful for tests that need specific mapping contents
- `real_fixtures_dir` — returns `Path` to `fixtures/real/`
- `real_xlsx_files` — returns a list of `.xlsx` files found in `real_fixtures_dir` (may be empty)

### `test_parse_fullnames.py`
Tests for `parse_fullnames(df: pd.DataFrame, fullname_col: str) -> pd.DataFrame`.

**Note to Claude Code:** some tests in this file assume a fix to the current behavior where any token ending in `.` is treated as a middle initial (which misclassifies suffixes like `"Jr."`). The tests marked below with `# FAILING UNTIL BUG FIX` should fail against the current implementation. Do not modify `parse_employer_bu.py` to make them pass — that fix is a separate task the user will do next.

For each test, build a minimal one-column DataFrame, run the function, and assert on the resulting `Last`, `First`, `Middle` columns.

- `test_parse_fullnames_standard`: `"Smith, John A."` → `("Smith", "John", "A.")`
- `test_parse_fullnames_no_middle`: `"Smith, John"` → `("Smith", "John", "")`
- `test_parse_fullnames_multiple_first_no_middle`: `"Smith, John Paul"` → `("Smith", "John Paul", "")`
- `test_parse_fullnames_multiple_first_with_middle`: `"Smith, John Paul A."` → `("Smith", "John Paul", "A.")`
- `test_parse_fullnames_hyphenated_last`: `"Smith-Jones, Alex"` → `("Smith-Jones", "Alex", "")`
- `test_parse_fullnames_apostrophe_last`: `"O'Brien, Sean"` → `("O'Brien", "Sean", "")`
- `test_parse_fullnames_compound_last`: `"García López, María"` → `("García López", "María", "")`
- `test_parse_fullnames_extra_whitespace`: `"  Smith , John  "` → `("Smith", "John", "")` — note: this depends on upstream `load_list` stripping; if `parse_fullnames` is called directly on un-stripped data, document current behavior
- `test_parse_fullnames_suffix_jr`: `"Smith, John Jr."` → `("Smith", "John Jr.", "")` # FAILING UNTIL BUG FIX
- `test_parse_fullnames_suffix_sr`: `"Smith, John Sr."` → `("Smith", "John Sr.", "")` # FAILING UNTIL BUG FIX
- `test_parse_fullnames_suffix_iii`: `"Smith, John III"` → `("Smith", "John III", "")`
- `test_parse_fullnames_multiple_commas_raises`: `"Smith, Jr., John"` → raises `ValueError`
- `test_parse_fullnames_no_comma_raises`: `"Smith John"` → raises `ValueError`
- `test_parse_fullnames_empty_string_raises`: `""` → raises `ValueError`
- `test_parse_fullnames_whitespace_only_raises`: `"   "` → raises `ValueError`
- `test_parse_fullnames_preserves_row_count`: input df of N rows → output df of N rows
- `test_parse_fullnames_invertibility_check`: write a test where the reconstructed fullname would not equal the original, confirm `ValueError` is raised
